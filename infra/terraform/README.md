# Giano infrastructure

Terraform for Giano's AWS deployments. The design, the decisions behind it and the cost model
live in [`specs/DEV-INFRASTRUCTURE.md`](../../specs/DEV-INFRASTRUCTURE.md); this file is the
operator's short form.

Giano is never centrally hosted — every client project runs the containers itself. What is here
provisions **Applied Blockchain's own dev environment**, not a client's.

```
bootstrap/            the S3 state bucket. Applied once, with a local backend.
envs/dev/             the dev root module. Base Sepolia, eu-west-2.
modules/
  network/            VPC, subnets, IGW, S3 endpoint, four security groups
  dns/                Route 53 child zone, ACM certificate + validation
  alb/                one ALB, HTTPS listener, HTTP->HTTPS redirect, 404 default
  ecs-cluster/        cluster, Cloud Map namespace, shared task execution role
  ecs-service/        one Fargate service, end to end
  ecr/                repository + lifecycle policy
  rds/                Postgres, generated password, composed DSN into SSM
  scheduler/          EventBridge scale-to-zero
  github-oidc/        the CI deploy role
```

## What it builds

Four public hostnames on one ALB, five Fargate services, one RDS instance:

| Hostname | Service |
|---|---|
| `wallet.dev.<domain>` | the wallet origin — **passkeys bind to this name** |
| `api.dev.<domain>` | `wallet-api` |
| `app.dev.<domain>` | the demo dApp |
| `paymaster.dev.<domain>` | the paymaster operator console |

The Alto bundler is the fifth service and has no public listener: it is reachable only from
`wallet-api`, over Cloud Map.

## Prerequisites

- Terraform **>= 1.10** (the S3 backend's native locking; there is no DynamoDB table)
- An AWS account with administrative access for the first apply
- A parent DNS zone you can add an `NS` record to
- A Base Sepolia RPC endpoint
- `GianoPaymaster` deployed on Base Sepolia — **there is no registry entry for it on 84532**

## Bring-up

Not a single apply. The full runbook is
[spec §16](../../specs/DEV-INFRASTRUCTURE.md#16-bring-up-runbook); the shape of it:

```sh
# 1. the state bucket
cd bootstrap && terraform init && terraform apply
#    put the bucket name into envs/dev/backend.tf

# 2. the DNS zone, on its own — the delegation is manual and ACM blocks on it
cd ../envs/dev
cp terraform.tfvars.example terraform.tfvars   # edit it
terraform init
terraform apply -target=module.dns
terraform output name_servers                  # add these as an NS record in the parent zone

# 3. deploy and provision GianoPaymaster on Base Sepolia, fund the Alto executor

# 4. the secrets Terraform will not write (see below)

# 5. everything else. Services fail to start: ECR is empty. Expected.
terraform apply

# 6. push images, migrate, provision sponsorship
```

## Secrets

No private key is ever a Terraform variable or a `tfvars` file — that is how keys reach state,
and state reaches a bucket someone can read. Terraform creates these parameters with a
placeholder value and then ignores their contents forever:

```sh
aws ssm put-parameter --overwrite --type SecureString \
  --name /giano/dev/rpc-url --value 'https://base-sepolia.g.alchemy.com/v2/...'

aws ssm put-parameter --overwrite --type SecureString \
  --name /giano/dev/sponsorship-signer-key --value '0x...'

aws ssm put-parameter --overwrite --type SecureString \
  --name /giano/dev/alto-executor-key --value '0x...'

aws ssm put-parameter --overwrite --type SecureString \
  --name /giano/dev/alto-utility-key --value '0x...'
```

`terraform output ssm_parameters` lists them. The database DSN, the metrics token and the
tenant admin key are generated by Terraform and land in state, which is why the state bucket is
private, versioned and encrypted.

## Day-to-day

```sh
terraform output urls                        # the four hostnames
terraform output -raw tenant_admin_key       # for the admin API
terraform output ssm_parameters              # what a human must populate

# reach the database — there is no bastion
aws ecs execute-command --cluster giano-dev --task <id> \
  --container wallet-api --interactive --command /bin/sh

# run the migrations
aws ecs run-task --cluster giano-dev --launch-type FARGATE \
  --task-definition "$(terraform output -raw migrate_task_definition)" \
  --network-configuration "$(terraform output -raw run_task_network_config)"
```

## Two things that will surprise you

**The environment is off outside working hours.** EventBridge sets every service to zero at
19:00 UTC on weekdays and back to one at 07:00, and Friday's shutdown holds until Monday. The
symptom is a 502 from the ALB. Set `enable_schedule = false` for a demo week.

**`rp_id` is irreversible.** Every passkey binds to `wallet.dev.<domain>`. Renaming that host
orphans every credential created against it — settle the domain before the first apply.

## Costs

~$77/month with the schedule, ~$139/month without;
[spec §12](../../specs/DEV-INFRASTRUCTURE.md#12-cost) itemises it. The ALB is the largest fixed
line and cannot be scheduled away.

## Adding staging

`envs/staging` is a second root module over the same modules, not a fork.
[Spec §18](../../specs/DEV-INFRASTRUCTURE.md#18-non-goals-and-the-path-to-staging) lists exactly
what it changes — and note that `GIANO_DEPLOYMENT_CLASS=production` is blocked until the HSM
signer adapter exists.
